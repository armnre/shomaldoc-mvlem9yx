# داده‌های رشته و گرایش کارشناسی ارشد

**منبع:** فایل «رشته‌ها و مقاطع.xlsx»، شیت «همه رشته‌ها». شیت‌های «فنی و مهندسی»، «علوم انسانی» و «تربیت بدنی» زیرمجموعهٔ همین شیت هستند و برای جلوگیری از رکورد تکراری کنار گذاشته شدند. شیت «خلاصه» فقط برای تطبیق شمارش‌ها استفاده شد.

| شاخص | مقدار |
|---|---|
| کل رکوردهای منبع (همهٔ مقاطع) | 70 |
| رکوردهای کارشناسی ارشد | **37** |
| رشته‌های یکتا (دانشکده + رشته) | **21** |
| رکوردهای دارای گرایش | **28** |
| رشته‌های بدون گرایش («—») | 9 |
| رکورد تکراری | 0 |

تطبیق با شیت «خلاصه»: فنی‌ومهندسی 23 + علوم انسانی 10 + تربیت بدنی 4 = 37 ✔

مقاطع کنارگذاشته‌شده: کارشناسی (22)، کارشناسی ناپیوسته (7)، کاردانی (2)، دکتری (2).

## مدل داده
از جدول موجود `Programs` (name, specialization, degree, isActive) استفاده شده و مدل موازی ساخته نشده است. فقط ستون nullable `faculty` به‌صورت افزایشی اضافه می‌شود. علامت «—» به `specialization = NULL` تبدیل شده است.

## واردسازی
```bash
cd /opt/shomaldoc/server
set -a; . ./.env; set +a
npx tsx --tsconfig tsconfig.json scripts/seed-masters-programs.ts --dry-run
npx tsx --tsconfig tsconfig.json scripts/seed-masters-programs.ts
```
این اسکریپت idempotent است. کلید طبیعی آن (مقطع، رشته، گرایش) است، داخل یک تراکنش اجرا می‌شود و هیچ رکوردی را حذف یا غیرفعال نمی‌کند.

## ابهام‌ها
- «حسابداری» و «حسابداری قضایی» دو رشتهٔ جدا در منبع هستند و همان‌طور حفظ شده‌اند.
- در منبع، «آسیب‌شناسی ورزشی و تمرینات اصلاحی» با گرایش «تمرینات اصلاحی» آمده است و همان‌طور حفظ شد.
- اتصال برنامه‌ها به جدول `Departments` (گروه آموزشی) نیاز به تعیین گروه هر رشته توسط دانشگاه دارد و خودکار انجام نشده است.

## دور دوم
- آمار در این دور دوباره با اجرای واقعی seed روی دیتابیس آزمون محاسبه شد: **37 رکورد، 21 رشتهٔ یکتا، 28 رکورد دارای گرایش** (پس 9 رکورد بدون گرایش). اجرای دوم: `0 inserted, 37 already` (تکرارپذیر). `--dry-run` چیزی نمی‌نویسد (تست `stages.test.ts`).
- انتخاب دانشکده ← رشته ← گرایش اکنون یکی از مراحل فرم پروپوزال است و ارسال پروپوزال بدون آن در Backend رد می‌شود.
